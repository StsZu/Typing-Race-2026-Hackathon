# Політика даних

## Принцип

Кожен набір зберігається окремо разом із відомостями про джерело та ліцензію. Репозиторій не надає спільну ліцензію стороннім словникам і навчальним матеріалам.

## Статуси

- PUBLIC — є зафіксована ліцензія, яка дозволяє поширення на зазначених умовах.
- REVIEW_REQUIRED — матеріал збережено, але відкриту ліцензію не підтверджено.
- EXCLUDED — службові або локальні файли, які не є частиною пакета.

Статус кожного набору наведений у [manifest.yml](../dictionaries/manifest.yml).

## Додавання набору

Для нового набору потрібно:

1. створити окремий каталог у відповідній мові;
2. зберегти оригінальний файл ліцензії;
3. записати джерело, ревізію, формат і кількість записів у маніфесті;
4. перевірити кодування та структуру;
5. додати SHA-256;
6. описати потрібну атрибуцію;
7. не позначати набір PUBLIC без підтвердженої ліцензії.

## Похідні дані

Очищення, нормалізація, фільтрація та побудова частотних комбінацій виконуються у проєкті учасника. Похідний набір повинен містити опис алгоритму та посилання на всі вихідні набори.

## Вимоги до застосунків

- не показувати сирі слова без контентної перевірки;
- не підміняти українські літери і, ї, є та ґ;
- документувати нормалізацію апострофів і Unicode;
- не надсилати тексти або прогрес користувача зовнішньому AI без явного повідомлення;
- не зберігати ключі API у клієнтському коді.

## Матеріали для перевірки

TT, копії Typing-race-2026 та радіодиктанти не додані до gitignore, але мають статус REVIEW_REQUIRED. Перед публічним запуском організатор має окремо підтвердити дозволений режим їх використання.
